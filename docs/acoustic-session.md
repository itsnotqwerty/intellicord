# Offline Acoustic Session Lifecycle

[AcousticSession](../src/acoustic/session.rs) wraps the existing chunk-to-repetition pipeline in an explicit in-process lifecycle. It is an offline library contract for future capture integration, not a sensor, consent dialog or enforcement mechanism against arbitrary code in the same process. Existing direct analyzers and examples remain available and unchanged.

The separate [explicit PipeWire CLI prototype](acoustic-capture.md) now consumes the untimed buffered controller from a foreground, consent-gated command. It does not change library activation semantics or add capture to existing analyzers/injector startup. Live compatibility and integrated per-session capture UI remain unverified or unfinished.

## Timed Activation And Output

[TimedAcousticSession](../src/acoustic/session/timed.rs) adds a separate lifecycle around the [interval-bearing pipeline](acoustic-foundation.md). It starts stopped. `start(sample_clock_mapping)` consumes one validated mapping, fixing its format, source/sample origin, bracket, rate-error bound and horizon for that activation. `start_encoded(mapping, encoding)` additionally binds encoded input to one declared encoding. Each successful start returns a fresh `SessionPermit`, using the same opaque identity mechanism as the untimed wrapper. Repeated starts return `AlreadyActive` without changing current processing or encoding; the unused supplied mapping is consumed and dropped. Stop/fault recovery requires explicit start with a fresh mapping; there is no clock rebase, automatic restart or reconnect.

`push(&permit, absolute_sample_position, normalized_pcm)`, `push_bytes(&permit, position, encoding, bytes)` and `push_planes(&permit, position, encoding, samples_per_channel, planes)` all return opaque `TimedSessionOutput` envelopes rather than bare batches. Inactive/current-permit checks precede decoding, allocation or input inspection. Stale/foreign permits, including permits from untimed sessions, cannot change processing state. Optional encoding checks follow permit validation and precede conversion, timeline and clock checks. A current mismatch returns `FormatChanged` and faults as `SessionFault::Producer(ProducerFailure::FormatChanged)`. Ordinary starts remain encoding-unbound; normalized input intentionally bypasses the encoding declaration. Trusted callers may mix paths on one consistent absolute sample timeline. This checks declarations, not actual source metadata, permissions or consent.

Successful input retains existing partial/gap handling and interval-bearing output. `accept_output(envelope)` consumes an envelope and checks that its activation is still active and current before returning `AssemblyBatch<TimedRepetitionFeatures>`. Stop/fault makes pending envelopes inactive; after restart, old or foreign envelopes are stale. Envelope fields are private and the type has no `Clone`, `Debug` or serialization implementation. No bare-output convenience method bypasses acceptance in this wrapper. Returned summaries still contain sensitive audio-derived features and timing; they are not anonymous or automatically retained by the session.

Any processing error from the current activation drops the assembler, partial PCM, comparison history and clock mapping. Frame/conversion errors return `SessionError::InvalidFrame`; clock failures return `SessionError::InvalidClock(ClockError)` and record the additive `SessionFault::Clock(ClockError)` status variant. For example, expiry serializes as `{"state":"faulted","error":{"clock":"expired"}}`. The other bounded clock labels are `invalid_anchor`, `before_anchor` and `overflow`; some are normally rejected during mapping construction rather than processing. Existing frame and producer status forms remain unchanged. Consumers must handle the additive clock object, not assume all errors are strings. Subsequent inactive callbacks preserve the first accepted fault. This intentionally differs from standalone timed-assembler atomic retry: a rejected current chunk cannot be retried under the faulted permit.

`report_failure(&permit, reason)` supports the existing source-loss, format-change and input-overflow reasons with the same permit-first checks and teardown. `stop()` unconditionally drops active processing and sets stopped status; repeated stops are harmless. Dropping the session also drops its assembler. Ordinary PCM overwriting/destruction is not secure zeroization. Stopping this library processor does not close an actual device, revoke OS permissions or erase already returned output.

This wrapper adds no output FIFO, health accounting, expiry of caller-owned results, delivery ordering, worker, locking or final-delivery synchronization. Callers can retain arbitrarily many envelopes or accepted batches; per-push processing remains bounded, but total caller retention is not. Acceptance is a point-in-time check: stop can occur after acceptance and before downstream delivery, so a future owning controller must serialize final delivery with revocation. Active status means processing is available, not capture liveness, source verification or calibrated synchronization. Sample-clock assumptions and source-time horizon limitations still apply. No capture, installation or live activation occurs.

Six [timed-session tests](../tests/acoustic-timed-session.rs), run with `cargo test --test acoustic-timed-session`, cover multiformat/all-encoding batch equivalence, all encoding pairs for byte and plane paths, rejected-start isolation, stale/foreign callbacks and outputs, conversion/clock faults and serialization, producer failures, stop/restart revocation and fresh repetition warmup. Existing untimed session and buffered-controller APIs remain unchanged apart from additive typed clock error/status variants.

## Buffered Timed Output

[BufferedTimedAcousticSession](../src/acoustic/session/timed/buffered.rs) owns a `TimedAcousticSession` and a FIFO of at most `OUTPUT_QUEUE_CAPACITY` (eight) tagged timed batches. `start(mapping)`, `start_encoded(mapping, encoding)`, `stop()`, `report_failure`, `status()` and all three input methods retain the direct timed lifecycle's contracts. Input methods return `Result<(), SessionError>` rather than exposing envelopes; `pop()` consumes and validates the oldest envelope before returning `Result<Option<AssemblyBatch<TimedRepetitionFeatures>>, SessionError>`. Empty queues return `Ok(None)`, even when inactive. No API exposes the inner processor or permits injecting external output. The direct timed API remains available and does not gain a queue automatically.

Each successful push occupies one batch slot, including partial-only output with no completed frames. Each batch contains at most four summaries, so steady retained output is at most eight batches/32 summaries. A ninth successful processing push first produces its bounded batch, then faults with `OutputOverflow`, drops processing/clock state and discards all nine batches (at most 36 transient summaries). Invalid current input retains conversion/frame/clock/encoding fault precedence even at capacity and does not count as a successful processed batch or output overflow. Stale/foreign callbacks and rejected active starts preserve the full queue and current mapping/encoding. Accepted producer failures, current input faults and stop discard the entire backlog. Explicit restart starts with no queued output, partial PCM or comparison history; prior permits cannot affect it. Dropping the owner drops its queue and processor without a final observable health snapshot.

`pending_batches()` and schema-version-1 `health()` reuse `OutputHealth` and its existing interpretation: processed/delivered/discarded batch and summary counts, pending counts, overflow events and queue high-water depth. Lifetime counters survive restart and saturate at `u64::MAX`; before saturation, processed equals delivered plus discarded plus pending separately for batches and frames. Empty-feature batches count as one batch/zero frames. Rejected input generates no processed output. Delivery means returned by `pop`, not downstream receipt. The snapshot contains no features, PCM, mapping values or identifiers, and active status is not capture liveness. The additive clock-fault status form described above can appear in these snapshots.

These are logical retention/work bounds, not measured allocations, RSS, CPU or real-time budgets. The queue retains summaries, not additional raw PCM; the processor still retains its bounded partial PCM and audio-derived comparison state. Returned batches can be retained without limit by the caller and cannot be recalled. `pop` validates activation at return time only; final delivery must still be serialized with stop/fault by a future owning integration. There is no input queue, TTL, worker, locking, capture, source verification, actual clock calibration, sensor-bus/UI routing or OS stream cleanup. Ordinary destruction is not secure zeroization.

Run `cargo test --test acoustic-timed-buffering` for five public regressions covering multiformat/all-encoding mixed-path equivalence, FIFO partial/gap/warmup metadata, maximum and empty-batch overflow, fault precedence, stale callbacks at capacity, restart/stop isolation, lifetime accounting and health shape. A separate unit test exercises saturation through delivery and overflow. No devices or Discord process are accessed.

## Activation And Input

`AcousticSession::default()` is stopped and owns no assembler. `start(format, origin_ns)` creates fresh processing state and returns an opaque, cloneable `SessionPermit`. Calling `start` while active returns `AlreadyActive`, preserving existing analysis. A stopped or faulted session requires a fresh explicit `start`; there is no automatic restart. Format construction remains validated by `Format::new`.

`push(&permit, absolute_sample_position, pcm)` requires the permit from that activation. Permits are private shared-allocation identities, not numeric IDs, serialized tokens or credentials. A permit from an earlier activation or another wrapper returns `StalePermit` before validating samples or mutating state. Holding a clone does not prevent stop or fault teardown. Inactive pushes return `Inactive` regardless of the supplied permit. Calls require exclusive mutable access; the wrapper does not add threads, locks or queues.

Successful pushes retain the [existing assembler contract](acoustic-foundation.md): bounded channel-aligned chunks, checked sample-clock mapping, summary-only output and gap handling. Forward gaps are accepted, reset comparisons, and report skipped/discarded samples; they do not themselves fault the session. A gap does not prove a capture failure or identify its cause.

Unlike the lower-level assembler's atomic error/retry behavior, any assembler error from a correctly authorized push faults this wrapper. It drops the assembler, records a typed reason in `SessionStatus::Faulted`, and returns `InvalidFrame(FrameError)`. Subsequent input is inactive until explicit restart. Reasons cover invalid length, invalid sample, invalid time and the underlying unsupported-format category. This deliberate fail-closed policy is not automatic capture recovery. Unsupported formats are ordinarily rejected before activation by `Format::new`; invalid timestamp origins may instead fault when the first push is validated.

`status()` reports `Stopped`, `Active` or `Faulted { error }` and supports privacy-limited serialization. Active means only that this in-memory processor is activated, not that a device is capturing, data is arriving or the sensor is healthy. There are no IDs, PCM, device metadata or feature summaries in status.

## Tagged Output Delivery

`push_tagged(&permit, absolute_sample_position, pcm)` performs the same processing as `push`, including the same validation, gap and fault semantics, but returns an opaque `SessionOutput`. Its batch and activation identity are private; callers cannot construct, retag or inspect it through public fields. The wrapper deliberately implements neither serialization, `Debug` nor `Clone`, and contains summaries only, not PCM. Holding a queued output does not keep the assembler alive.

`accept_output(output)` consumes the wrapper and returns its `AssemblyBatch<RepetitionFeatures>` only if the originating activation is still active. Stopped/faulted sessions return `Inactive`; a newer activation or another active wrapper returns `StalePermit`. Rejection drops the output without changing current status, pending PCM or analysis history. Old outputs cannot become current after restarting with identical format and timestamps because each activation has a fresh allocation identity.

Acceptance is a point-in-time check, not a revocable borrow or a delivery guarantee. Once returned, the untagged batch is caller-owned and cannot be recalled. A future controller must coordinate acceptance and final delivery with revocation under the same controller serialization/lock; accepting, releasing the lock, and delivering after stop would defeat that integration policy. Keep outputs tagged until final delivery, not merely until dequeueing to another asynchronous stage. Do not hold a real-time capture callback while running analysis or delivery.

This checks activation identity, not ordering or freshness within one active session. Valid same-session results can be accepted out of order or delayed indefinitely while that activation stays active. No output sequence, TTL, automatic queue, thread or consumer is introduced. Existing `push` intentionally remains the untagged synchronous API; it does not gain delayed-delivery protection. Neither API establishes a security boundary against arbitrary code in the same process.

Every output retains one existing bounded batch (at most four summaries, including gap and partial-buffer metadata) and one permit reference. Caller-retained output count and lifetime are unbounded by this API, so future queues need explicit capacity, overflow handling and disposal on stop/fault. Stop invalidates acceptance, but does not erase or proactively free queued wrappers. Ordinary dropping is not secure zeroization.

Four [output integration tests](../tests/acoustic-output.rs) compare tagged/direct batches through partial input, a gap and a maximum batch; check post-stop/restart rejection; cover analyzer- and producer-fault rejection; and verify foreign-session rejection without invalidating the origin. There is no compile-fail regression test for private field visibility, serialization or cloning; runtime checks do not protect those API-shape constraints.

## Bounded Output Controller

`BufferedAcousticSession` owns an `AcousticSession` and a private FIFO of tagged outputs. It defaults to stopped, exposes `start`, `status`, `stop`, permit-checked `report_failure`, `push`, `pop` and `pending_batches`, and does not expose mutable access to the underlying session. Existing direct session APIs are unchanged. Calls are synchronous under exclusive mutable access; this adds no worker, input PCM queue, scheduling or runtime routing.

`push` returns `Ok(())` after retaining one batch. `OUTPUT_QUEUE_CAPACITY` is eight batches, each at most four summaries. Empty-feature batches still count because they carry gap and partial-buffer metadata; small chunks can fill the queue before any frame completes. `pop` consumes and validates the oldest tagged output, returning `Ok(Some(batch))`, or `Ok(None)` when empty. Popping frees a slot, without sorting, coalescing or dropping metadata.

Validation and processing occur before capacity checking. Stale/foreign permits cannot fault or alter a full current queue; invalid current input retains its analyzer error precedence. A ninth successful processing push drops the new output, clears all eight queued outputs and processing state, returns `SessionError::OutputOverflow`, and records `SessionFault::OutputOverflow`, serialized as `{"state":"faulted","error":"output_overflow"}`. This is separate from producer-reported input overflow. There is no automatic restart or output replay. At most eight batches are retained between calls; the overflow push transiently holds nine (at most 36 summaries) before teardown. These are logical bounds, not measured RSS, allocation-free guarantees or a global limit across controllers.

Explicit stop and accepted analyzer/producer faults clear the owned backlog immediately. A fresh start has fresh analysis state and an empty queue. Repeated start while active, stale callbacks and repeated reports while faulted preserve the current queue/status contract. Normal destruction drops the owned backlog and session. Cleanup is ordinary dropping, not secure zeroization.

The queue guarantees FIFO order only within this controller. There is no TTL or delivery scheduling. Once popped, summaries are caller-owned, unbounded by this queue and cannot be recalled. Final downstream delivery must still be serialized with revocation; dequeuing into another asynchronous stage does not solve that requirement. Unconditional `stop` remains a controller action, not an authorized producer callback. Actual stream shutdown and discarding external producer buffers remain unimplemented.

Six [buffering integration tests](../tests/acoustic-buffering.rs) cover direct-output FIFO equivalence, partial/gap/maximum batches, capacity and overflow teardown, freeing slots, partial-only backlog, stale/foreign callbacks at capacity, active-start rejection, analyzer-before-overflow precedence, first-fault preservation, stop/fault cleanup and restart isolation. Tests use supplied PCM only, with no devices or live Discord interaction.

## Permit-Checked Byte Input

`BufferedAcousticSession::push_bytes(&permit, absolute_sample_position, encoding, bytes)` connects the [bounded raw PCM converter](acoustic-foundation.md) to the owning lifecycle. The activation fixes sample rate and channel count; callers cannot supply a different `Format` per chunk. `PcmEncoding` is declared explicitly on each call. Ordinary `start` remains encoding-unbound; optional `start_encoded` binds that declaration as described below. Neither mode negotiates with an OS source or detects a producer lying about encoding, channel positions or sample rate. Real source format changes must still be reported and require new validated activation.

Inactive sessions return `Inactive` and stale/foreign permits return `StalePermit` before decoding or allocating PCM, without changing health, pending summaries or current analysis. A current permit first undergoes whole-chunk conversion validation. A conversion length/sample error drops the active assembler and queued outputs, records the matching existing `SessionFault`, and returns `InvalidFrame`. It counts retained summaries as discarded, but generates no processed batch or output overflow event. Later inactive callbacks preserve the first fault; recovery requires explicit restart.

Valid decoded samples use the existing normalized `push` path, including absolute sample positions, timestamp validation, partial/gap metadata, repetition resets, FIFO bounds and output accounting. Conversion validation precedes timestamp and queue-capacity checks, so malformed current input remains a conversion fault even at capacity. A valid ninth push still faults with output overflow and accounts for all nine discarded batches. Callers may mix normalized and byte input, but must preserve a single consistent sample timeline. This synchronous exclusive-borrow API adds no asynchronous handoff or final-delivery synchronization.

The converter allocates at most four frames of temporary normalized PCM (245,760 logical bytes at 96 kHz/eight channels), in addition to the assembler's existing partial PCM and derived state. The local vector is ordinarily dropped after processing; invalid tails and other errors also use ordinary drop, not secure zeroization. Input bytes remain caller-owned. No bytes or decoded PCM are queued, serialized or persisted by this method. Allocation, decoding and FFT processing are not suitable for an unmeasured real-time capture callback.

Six [byte-lifecycle integration tests](../tests/acoustic-byte-session.rs) cover decoded/direct batch and health equivalence across all four encodings and three format combinations, partial input/gaps/warmup, current conversion errors and first-fault preservation, stale/foreign malformed callbacks at capacity, conversion-before-overflow precedence, valid overflow accounting, timestamp errors and restart with a new channel count. These use generated/supplied buffers only. No PipeWire connection, device, file reader, worker, capture permission control or runtime routing is added.

## Permit-Checked Plane Input

`BufferedAcousticSession::push_planes(&permit, absolute_sample_position, encoding, samples_per_channel, planes)` connects the [planar/strided converter](acoustic-foundation.md) to the same owning lifecycle as packed bytes. The activation fixes rate/channel count, and optional `start_encoded` binding applies to both methods. Validation order is inactive/current permit, optional encoding match, whole-view conversion, then normalized timeline/queue processing. Rejected stale/foreign input cannot change the active queue or health, including malformed views at capacity. A current encoding mismatch faults as producer format change before inspecting view ranges or values.

Current invalid view dimensions, strides, ranges or selected samples fault with the converter's existing `InvalidFrame` category, drop processing state and discard/account for retained output. They generate no processed batch or output overflow event, even at capacity or with invalid timestamps. Later inactive calls preserve the accepted fault. Valid conversion shares normalized input's sample-clock mapping, partial/gap handling, repetition reset, eight-batch FIFO and ninth-batch overflow accounting. Explicit restart supplies fresh format/encoding and a fresh permit. Callers may mix normalized, packed and plane input on one consistent absolute sample timeline; layout itself is not bound to an activation.

All plane ranges are checked before allocating at most four frames of temporary normalized PCM. Borrowed backing slices and numeric strides are not size-capped, and unselected padding is not validated. Views and backing buffers are not retained; the temporary vector is ordinarily dropped after processing, not securely zeroized. Existing bounded partial PCM retention still applies in the assembler. This synchronous conversion and processing is not a measured real-time callback and adds no source identity/permission checks, OS buffer mapping, PipeWire negotiation, capture, worker, runtime routing or actual stream cleanup.

Five [plane-lifecycle integration tests](../tests/acoustic-plane-session.rs), run with `cargo test --test acoustic-plane-session`, cover all four encodings across three formats with partial/gap/warmup and health equivalence, stale/foreign malformed callbacks at capacity, encoding mismatch precedence, conversion faults and first-fault preservation, valid overflow accounting, and mixed plane/packed input with format-isolated restart. The standalone converter remains stateless. The encoding-bound activation rules below apply equally to `push_bytes` and `push_planes`.

## Encoding-Bound Activation

`BufferedAcousticSession::start_encoded(format, origin_ns, encoding)` optionally binds one byte encoding to an activation, in addition to its fixed rate/channel count. It returns the existing fresh `SessionPermit`. A repeated `start` or `start_encoded` while active returns `AlreadyActive`, preserving binding, partial PCM, queue and health. Explicit stop/fault followed by a fresh start can select another encoding or return to ordinary encoding-unbound `start`; no automatic renegotiation or reconnect occurs.

`push_bytes` checks inactive/current permit first, then compares encoding before decoding, timestamp checks or queue capacity. A current mismatch returns the new `SessionError::FormatChanged`, reports the existing `SessionFault::Producer(ProducerFailure::FormatChanged)` and clears processing and backlog with normal discard accounting. Status serialization stays `{"state":"faulted","error":{"producer":"format_changed"}}`. No new output or output overflow event is counted. Thus an empty/malformed mismatched chunk still reports format change, even at capacity. Stale/foreign mismatches cannot change current binding or queue; later inactive callbacks preserve the first accepted fault.

Matching declarations follow the existing byte conversion path unchanged, including conversion faults and bounded temporary PCM. Encoding binding is not validation of the actual bytes or capture source. It cannot detect bytes mislabeled with the expected encoding, rate or channels. Normalized `push` intentionally remains available, since its values already have the normalized format; it neither checks nor changes the byte encoding binding. Trusted callers may mix those APIs on one consistent sample timeline. This library API is not a security or consent boundary against code in the same process, and no UI, negotiated PipeWire format or actual capture is added.

Five [encoding-contract integration tests](../tests/acoustic-encoding.rs) cover all sixteen expected/supplied encoding pairs, successful matching and normalized input, mismatch teardown/accounting, stale/foreign mismatches at full capacity, inactive and first-fault preservation, mismatch precedence, rejected starts preserving binding and explicit restarts with a different format/encoding or unbound mode.

## Output Health Accounting

`BufferedAcousticSession::health()` returns a copyable, serializable `OutputHealth` schema version 1 snapshot. It contains current status, capacity in batches, pending batch/frame counts, processed/delivered/discarded batch/frame counts, output overflow event count and the retained queue's high-water batch count. `OutputCounts` counts completed feature summaries as frames; an empty-feature batch counts as one batch and zero frames. Reading health does not mutate state or retain additional audio-derived data. The snapshot has no PCM, features, identifiers, timestamps or device metadata.

Processed counts include every successfully computed batch, including the ninth batch that triggers output overflow. Invalid, stale or inactive pushes produce no batch and do not increment processed counts. Delivered means successfully returned by `pop`, not received, displayed or acted on downstream. Discarded counts include queued batches removed on explicit stop or accepted faults and the new overflow-triggering batch. Output overflow discards nine batches, not just the newest one. Producer-reported input overflow does not increment the output overflow event counter. Rejected callbacks and empty pops do not change counters.

Before saturation, processed equals delivered plus discarded plus pending, independently for batches and frames. Counts are lifetime totals for one controller, survive stop/restart, and saturate independently at `u64::MAX` rather than wrap; arithmetic conservation is no longer guaranteed after saturation. High-water counts retained batches only, so never exceeds eight. Counters are not persisted, resettable or global. Dropping the controller also drops its health; there is no final teardown report after destruction.

These metrics measure output disposition only. Discarded summaries are not a count of lost input samples or transitions, and partial PCM teardown is not counted as a completed frame. They are not capture health, liveness, lag, memory usage, throughput or detection accuracy. There is no runtime bus/UI consumer or active sensor connected. Four [health integration tests](../tests/acoustic-health.rs) cover conservation, serialization, empty batches, overflow, stop/fault/restart and rejected callbacks; a private unit test verifies saturation without billions of operations.

## Stop And Retention

`report_failure(&permit, ProducerFailure)` provides the producer-side failure path without sending fabricated invalid PCM or invoking unconditional controller stop. Reasons are the bounded categories `SourceLost`, `FormatChanged` and `InputOverflow`; free-form messages, paths, device metadata and IDs are not accepted. The caller must report known conditions, not infer participant responsibility from them. These are producer assertions, not independently verified diagnoses.

A current permit returns `Ok(())`, immediately drops processing state and records `SessionFault::Producer(reason)`. Input remains inactive until a fresh explicit start; there is no reconnect or retry. A stopped/faulted processor returns `Inactive` without overwriting status, preserving the first accepted fault. A previous activation's or foreign wrapper's permit returns `StalePermit` while the processor is active, leaving the current partial buffer and history intact. Permit validation and transition happen under the same exclusive mutable borrow.

Serialized producer failures are source-labeled, for example `{"state":"faulted","error":{"producer":"source_lost"}}`. Existing analyzer faults retain their string forms such as `{"state":"faulted","error":"invalid_sample"}`. Consumers must handle the additional enum variant rather than assuming every `error` is a string. There is no runtime status consumer connected by this change.

A forward sample-position gap still uses normal assembler gap handling and does not automatically report an overflow. A worker that cannot safely continue after actual input overflow can explicitly report `InputOverflow`; format changes require new validated activation rather than silently changing the existing format. Neither path establishes a specific number of lost samples or fabricates features for missing input.

`stop()` is unconditional and idempotent. It drops all current processing state and sets `Stopped`, clearing any previous fault reason. It is a controller operation, not a producer callback authorized by a permit. A future asynchronous worker must not route an old producer's shutdown callback to unconditional `stop()` on a newer activation.

Stop, fault, and normal wrapper destruction drop the assembler and its partial PCM, FFT plan, spectrum and repetition history. Existing assembler destruction ordinarily overwrites its PCM buffer; derived allocations are not securely wiped. This is not cryptographic erasure. Previously returned summaries, caller-owned PCM, permit clones, worker buffers, OS caches and any explicit exports remain caller-owned. A fresh activation has a fresh origin, no pending samples and no previous comparison history. The caller must restart absolute sample positions for that activation.

Each active wrapper has the existing bounded analyzer state and one permit allocation. Permit clones can outlive a session, and retained clones are not capped by this API. Each independently constructed wrapper has its own bounds; the API does not impose a global session limit or resource budget. It is allocating synchronous code, not real-time callback code.

## Remaining Integration

A future controller must require explicit per-session user consent, verify an intended application-output source without microphone/system-monitor fallback, keep a visible capture indicator, and pass the activation permit only to the approved worker. On revocation/fault it must stop the actual stream, discard queued PCM and outputs, and reject results from older activations. None of those OS/UI/worker behaviors is implemented or proven by this wrapper.
