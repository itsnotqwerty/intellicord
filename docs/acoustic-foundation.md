# Acoustic Feature Foundation

These are offline Rust level/spectral feature processors and a chunk assembler, not an audio sensor or micspam detector. Nothing invokes them from the injector, renderer, or sensor bus. No PipeWire connection, device enumeration, microphone access, playback capture, file reader, worker, or listener is added.

## Try Synthetic Frames

```sh
cargo run --quiet --example analyze_synthetic_audio
cargo run --quiet --example assemble_synthetic_audio
cargo run --quiet --example analyze_synthetic_spectrum
cargo run --quiet --example assemble_synthetic_spectrum
cargo test acoustic::tests
cargo test acoustic::framing::tests
cargo test acoustic::spectral::tests
cargo test --test acoustic-pipeline
```

The example generates four short stereo frames in memory: silence, opposite-phase 1 kHz sine, a full-scale square wave, and silence after a timestamp gap. It prints feature summaries, not PCM, to stdout. It accepts no arguments and accesses no audio device. Redirecting stdout is an explicit user action; the implementation opens no output files.

The separate assembly example generates channel-aligned, non-frame-sized stereo chunks at 44.1 kHz. It prints two assembled feature frames followed by a simulated sample gap and a recovery frame. Five skipped samples per channel are reported separately from ten partial samples intentionally discarded per channel. Output contains feature/gap metadata, never PCM.

## Input Contract

[src/acoustic.rs](../src/acoustic.rs) exposes `Format::new` and `Analyzer::process`. Input is interleaved normalized `f32` PCM, with every sample finite and inside `[-1, 1]`. Sample rates must be between 8,000 and 96,000 Hz and divisible by 50; channel counts range from one through eight. This includes 44.1 kHz and 48 kHz. Each frame must contain exactly 20 ms of samples, at most 15,360 scalar values. Unsupported formats, empty/partial/oversized frames, NaNs, infinities, and out-of-range values are rejected rather than silently trimmed, normalized, or clamped.

The caller supplies the frame-start timestamp as monotonic nanoseconds, not wall time. End-time overflow, backwards time, and overlapping accepted frames are errors. Rejected calls do not change analyzer state. A contiguous frame must start exactly at the previous accepted end time and retain the same format. A timestamp gap or format change sets `discontinuity` and suppresses `rms_change`. The first accepted frame after construction/reset has no previous comparison and is not labeled as an observed gap. `reset()` discards continuity state, allowing a new timestamp origin.

A future capture adapter can use the offline assembler below to form exact frames, but still must validate and map PipeWire buffers and timestamps. It must explicitly reset after capture loss or source changes even when timestamps appear contiguous. These components cannot verify the caller's claimed clock, source, channel layout, or missing audio. Cross-clock synchronization, drift estimation, PipeWire format negotiation and resampling are not implemented here. Explicit supplied-byte conversion is available as described below.

## Supplied PCM Byte Conversion

[src/acoustic/pcm.rs](../src/acoustic/pcm.rs) exposes `decode_pcm_chunk(format, encoding, bytes) -> Result<Vec<f32>, FrameError>`. The caller must provide a validated `Format` and explicit `PcmEncoding`: `Signed16Le`, packed three-byte `Signed24Le`, `Signed32Le` or `Float32Le`. This is raw little-endian interleaved PCM, not WAV/container parsing, native-endian guessing or a negotiated PipeWire format. Bytes and channel order are preserved; no mixing, gain, clamping, resampling, padding, reordering or channel-position verification occurs.

Signed integers normalize by two to the power of their bit depth minus one. Negative full scale maps to `-1.0`; signed 16/24-bit positive full scale remains below `1.0`. Converting signed 32-bit samples to `f32` loses low-bit precision and can round positive full scale to `1.0`. Packed 24-bit values are placed in the high 24 bits of a signed 32-bit value and normalized by two to the power of 31, equivalent to signed 24-bit division by two to the power of 23. Float samples retain their finite values, including signed zero; nonfinite or out-of-range values are rejected, not clamped.

Input must be nonempty, contain complete scalar samples and channel groups, and fit at most `MAX_CHUNK_FRAMES` (four) 20 ms frames. Length validation occurs before allocating. At 96 kHz/eight channels this permits 61,440 samples, at most 245,760 input bytes and 245,760 logical output bytes, excluding caller copies and allocator overhead. These are per-call logical limits, not measured RSS, global retention or real-time budgets. Output allocation and conversion are synchronous.

Errors return no partial vector. The function owns no persistent state and does not advance clocks, fault a session, emit health or reset analyzers. The caller must handle conversion failure explicitly: preserve absolute positions if dropping input, or report a current-permit producer failure when continuation is unsafe. Do not silently hide lost bytes by relabeling later input contiguous. Decoded PCM is caller-owned sensitive data; nothing serializes or persists it here. Ordinary vector destruction, including on an invalid tail, does not securely zero memory. Caller-owned bytes remain untouched. No devices, files, workers or streams are opened.

Five [public conversion tests](../tests/acoustic-pcm.rs) cover extrema, low-bit sign/endian arithmetic against independent normalization, float boundaries and invalid tails, complete channel groups, maximum/oversized chunks, and decoded/direct chunk-to-repetition equivalence across all encodings at 8,050 Hz mono, 44.1 kHz stereo and 96 kHz/eight channels. Run `cargo test --test acoustic-pcm`. Explicit planar/strided views are supported below. Big-endian formats, automatic interpretation of padded 24-in-32 layouts, unsigned samples, source selection/consent, timestamp mapping from OS clocks and capture callback integration remain unimplemented.

For lifecycle-managed byte input, [the owning session controller](acoustic-session.md) offers `push_bytes`: it checks the activation permit before conversion, uses that activation's fixed rate/channel count, and faults/clears its backlog on current conversion errors. The standalone `decode_pcm_chunk` function remains stateless and does not change session state on its own. Neither path verifies an actual capture source or encoding negotiation.

## Planar And Strided Views

`decode_pcm_planes(format, encoding, samples_per_channel, planes)` accepts one borrowed `PcmPlane { bytes, offset_bytes, stride_bytes }` per channel and returns normalized interleaved samples in plane order. Each plane selects one scalar sample at `offset_bytes + sample_index * stride_bytes`. Separate channel slices represent planar audio; multiple views into one shared slice can represent interleaved audio with channel offsets and a whole-channel-group stride. One explicit encoding applies to all planes. This reuses the packed decoder's normalization and finite-range checks, with no resampling, mixing or channel-position verification.

There must be exactly the validated channel count of planes (one through eight), and a nonzero sample count of at most four frames per channel. Each stride must be at least one encoded sample wide, even for one sample. Checked multiplication/addition verifies every plane's last selected sample fits its borrowed slice before output allocation or sample decoding. Truncated planes, address overflow and invalid dimensions return `InvalidLength`. Invalid selected floats return `InvalidSample` without partial output. Different channel views may overlap or alias immutable input intentionally; within each plane consecutive selected samples cannot overlap. There is no unsafe pointer access.

Leading/trailing bytes and stride padding are ignored, including invalid float patterns in padding. The backing slices and numeric strides themselves are not capped: callers may reference a larger mapped buffer, but decoded sample count, selected bytes read and work remain bounded. At most 61,440 samples/245,760 logical output bytes are allocated per call. This is not a bound on caller-owned buffer memory or measured RSS. Only selected sample ranges are interpreted; successful conversion is not validation of the whole backing allocation. Packed 24-bit values may be selected with explicit offsets/strides, but the helper cannot infer a padded container's alignment or bit semantics.

Views are borrowed for the synchronous call only; no buffers, descriptors or pointers are retained. Output is caller-owned sensitive PCM and ordinary destruction is not secure zeroization. The function is stateless and does not check permits, alter session health, fault processing or advance sample clocks. A future adapter must validate OS buffer lifetimes/metadata, source identity, format and permissions before constructing views, and handle failures without hiding missing input. The [owning session controller](acoustic-session.md) now offers `push_planes` for permit-checked conversion, encoding binding, fail-closed teardown and shared queue accounting. Its existing `push_bytes` continues to accept tightly packed interleaved bytes only. PipeWire mapping remains unfinished.

Five [layout tests](../tests/acoustic-layout.rs), run with `cargo test --test acoustic-layout`, cover separate padded planes and shared interleaved slices, all four encodings across three rate/channel combinations, decoded/direct pipeline equivalence, maximum dimensions, plane-count mismatch, truncation/address overflow, full range preflight, ignored padding and invalid selected tails. No capture, devices, files, workers or runtime routing are introduced.

## Chunk Assembly

[src/acoustic/framing.rs](../src/acoustic/framing.rs) exposes `FrameAssembler`, `AssemblyBatch`, `SampleGap`, and `MAX_CHUNK_FRAMES` through the public acoustic module. Construct an assembler with a validated `Format` and a trusted monotonic origin corresponding to sample position zero. The format remains fixed; a different format requires a new instance.

`push(start_sample_per_channel, interleaved)` accepts nonempty normalized PCM chunks, no larger than four 20 ms frames, whose scalar length is divisible by the channel count. Chunks need not align to a feature-frame boundary, but must contain whole interleaved sample groups. The absolute starting sample position counts samples per channel, not interleaved scalar values, bytes, callback sequence, or nanoseconds. The first expected position is zero.

Timestamps are computed from the original anchor using integer arithmetic: origin plus the floor of absolute sample position times one billion divided by sample rate. Each frame is exactly 20 ms; this avoids cumulative truncation drift at 44.1 kHz even when chunks have arbitrary sizes or a recovery frame starts off the original frame grid. It does not estimate source clock drift or normalize clocks across processes.

- A contiguous chunk completes buffered PCM, emits zero to four feature frames in order, and retains only a sub-frame remainder. `buffered_samples_per_channel` describes that remainder. There is no padding, silent sample fabrication, or automatic flush of incomplete frames.
- A forward sample-position jump returns `SampleGap` immediately. `skipped_samples_per_channel` counts the known index jump, while `discarded_partial_samples_per_channel` counts pre-gap buffered samples intentionally removed. Neither is a count of lost Discord transitions or an estimate of unseen activity.
- A gap clears the partial frame and analyzer comparison state. The first completed recovery feature has `discontinuity: true` and no `rms_change`, even if its completion requires later chunks. Subsequent contiguous features resume comparison. Multiple gaps remain separately reported; gap metadata appears on the push that detected it, not necessarily the push that emits recovery features.
- Backwards/overlapping positions, invalid lengths/samples, position overflow, and mapped timestamp overflow reject the entire chunk before state mutation. Invalid data near the chunk's tail cannot produce earlier features from that chunk. If a rejected chunk is lost rather than retried, the next supplied absolute position must reflect that loss or the caller must reset.
- `reset(new_origin_ns)` discards a partial frame and returns its size per channel, clears analyzer history, restarts expected position at zero, and marks the first subsequent completed frame discontinuous. Use it for an explicit source restart even when positions would otherwise look contiguous. Discard counts are returned to the caller, not accumulated indefinitely.

This is a synchronous bounded helper, not a real-time PipeWire callback implementation: output vectors allocate, and no latency or CPU budget has been benchmarked. Capture callbacks will need a separate bounded worker handoff and explicit overflow/health reporting. No acoustic producer or observation stream is connected by this change.

## Source Clock Intervals

[src/acoustic/clock.rs](../src/acoustic/clock.rs) exposes immutable `SourceClockMapping`, `ClockInterval` and `ClockError` through the acoustic module. Construct `SourceClockMapping::new(source_anchor_ns, local_before_ns, local_after_ns, max_elapsed_ns, rate_error_ppm)` from a source-clock reading bracketed by backend monotonic readings. Both clocks must use nanosecond units; their epochs may differ. The caller must establish that the source reading occurred within the local bracket and that all subsequent source readings belong to the same continuously advancing clock domain. No actual clock is read, detected or verified by this helper.

For `map(source_ns)`, let `delta = source_ns - source_anchor_ns` and `drift = ceil(delta * rate_error_ppm / 1_000_000)`. Schema version 1 output is the closed interval `earliest_ns = local_before_ns + delta - drift`, `latest_ns = local_after_ns + delta + drift`. The supplied rate bound must limit the absolute difference between local elapsed nanoseconds and source elapsed nanoseconds over the mapped interval. It is not a measured oscillator tolerance, a calibrated confidence interval, or a reciprocal frequency estimate. For example, an anchor `(source=500, local_before=1000, local_after=1020)` with 100 ppm maps source `1000500` to `[1000900, 1001120]`. Outward integer rounding preserves sub-nanosecond uncertainty instead of silently truncating it. A zero rate bound is an explicit assumption of equal clock rates, not a default synchronization guarantee.

Construction rejects reversed local brackets, a zero horizon, or rate error above 1,000,000 ppm with `InvalidAnchor`. Rates from zero through 1,000,000 ppm are accepted; the upper endpoint allows no positive lower bound on local elapsed time. Mapping rejects source times before the anchor with `BeforeAnchor`, source elapsed time beyond the inclusive horizon with `Expired`, and intervals not representable in `u64` with `Overflow`. Wide integer intermediates avoid wrapping even at maximum source/local values. Errors do not mutate the mapping, so later valid readings remain usable. Out-of-order calls within the allowed horizon are intentionally permitted; this is not an event-order or replay guard.

The horizon limits source-time distance from the anchor, not backend wall age, capture liveness or callback delay. A frozen source clock never expires merely because local time passes. Bounds are conditional on caller assumptions: clock jumps/resets, suspend behavior, incorrect brackets, unknown transport delay or violated rate bounds can invalidate them. A future adapter must reject such conditions, obtain fresh validated anchors and explicitly restart/reset dependent processing; there is no automatic rebasing, drift fitting, reconnect or smoothing. Each mapping stores only five fixed numeric fields, with no vectors, PCM, device metadata or identities. Mapping is constant work with no heap allocation.

The existing assembler/session APIs still require one trusted point origin and do not carry timestamp uncertainty. Do not select an interval endpoint or midpoint and silently present it as exact feature time. The public composition test uses only an exact interval to supply an origin; nonzero interval propagation, source-clock-to-sample correlation, long-run sample-rate drift, backend session-domain checks and capture lifecycle integration remain unfinished. This helper changes neither existing feature schemas nor ingestion clock requirements, and adds no device access, worker, runtime sensor or participant attribution.

Five [public clock tests](../tests/acoustic-clock.rs), run with `cargo test --test acoustic-clock`, cover exact/bracketed arithmetic, signed scaled-integer checks of outward rounding, endpoint monotonicity, invalid anchors and rate bounds, expiry, full-width overflow, immutable errors, serialization and exact-origin composition at 44.1 kHz. These supplied integer cases establish arithmetic behavior only, not real clock calibration or capture compatibility.

## Sample Clock Intervals

`SampleClockMapping::new(source_mapping, format, source_origin_ns)` takes ownership of an existing `SourceClockMapping`, a validated `Format`, and the source-clock time corresponding to absolute sample position zero. Construction validates that origin through the source mapping, returning its existing before-anchor, expiry or overflow errors. Channel count does not affect timing: positions count samples per channel, not scalar interleaved samples. The mapping is immutable and independent of assembler/session state.

`map(sample_per_channel)` computes the absolute rational offset `sample_per_channel * 1_000_000_000 / sample_rate` with wide integer arithmetic. It adds the floor and ceiling separately to the source origin, maps both source endpoints, and returns the lower endpoint's `earliest_ns` and upper endpoint's `latest_ns` in the existing schema-version-1 `ClockInterval`. This preserves anchor uncertainty and source rate-error bounds, adding conservative outward rounding for fractional source nanoseconds. At 44.1 kHz, sample one is between source offsets 22,675 and 22,676 ns; a complete 882-sample frame is exactly 20,000,000 ns. Each call uses the absolute position, so rounding does not accumulate across chunks or frames. No midpoint or nominal exact backend timestamp is returned.

Both rounded source endpoints must fit `u64` and the source mapping's inclusive horizon. If the floor fits but the ceiling expires, the whole mapping fails with `Expired`; no partial interval is returned. Source-address and backend interval overflow return `Overflow`. Large sample positions are checked rather than wrapped. Failed calls do not change subsequent results, and repeated/out-of-order positions are allowed. The helper owns only fixed numeric state, performs constant arithmetic with no heap allocation, and retains no PCM or output history.

This assumes ideal sample cadence at the declared rate in the selected source-clock domain, and an exact caller-supplied sample-zero/source-time relationship. It does not infer that relationship from callbacks, account for sample-position/anchor uncertainty, measure actual device-rate drift, or correct clock resets/suspend. The source mapping's rate bound concerns source versus backend time, not the sample oscillator versus source time. An adapter must validate these separate assumptions, or provide a future uncertainty-aware cadence model, before using intervals as evidence. Source-time expiry still does not establish backend liveness. There is no activation identity, replay guard or automatic session fault handling in this standalone helper.

The optional timed assembler below attaches these intervals alongside explicitly nominal features; existing direct feature/session outputs remain unchanged and no timing data is routed into fusion. Consumers must preserve the interval, not choose an endpoint and silently label it exact. The prior exact-origin assembler test remains the only point-origin composition example. Actual capture-clock/sample correlation, lifecycle/fusion integration, runtime domain checks and PipeWire integration remain unfinished.

Five [sample-clock tests](../tests/acoustic-sample-clock.rs), run with `cargo test --test acoustic-sample-clock`, cover fractional rounding, bracket/rate composition, 10,000 absolute offsets for five rates and three channel counts, origin validation, both-endpoint expiry and integer overflow with valid calls after errors. These are arithmetic checks using supplied integers, not capture accuracy measurements.

## Interval-Bearing Repetition Assembly

`TimedRepetitionFrameAssembler::new(sample_clock_mapping)` owns the immutable mapping and a `RepetitionFrameAssembler` of the same format, with an internal nominal origin of zero. It accepts the existing normalized interleaved chunk contract through `push(absolute_sample_position, samples)`, returning `AssemblyBatch<TimedRepetitionFeatures>`. Existing level, spectral, repetition and session APIs are unchanged. Replacing the source/anchor requires dropping this assembler and constructing a new one; there is no in-place clock rebase or reset that might retain comparisons from the old clock.

Each schema-version-1 `TimedRepetitionFeatures` contains absolute `start_sample_per_channel` and exclusive `end_sample_per_channel`, plus `start_time` and `end_time` clock intervals mapped at those boundaries. `nominal_sample_clock_features` contains the unchanged nested repetition/spectral/level features. Its `frame_start_ns` is elapsed nominal sample-clock time from zero, and its 20 ms duration is nominal sample duration, not an exact backend timestamp or measured duration. No interval endpoint is substituted into those fields. The end interval describes the boundary immediately after the final sample, not the timestamp of the last scalar value. Marginal endpoint intervals are not independent probability distributions and do not supply a calibrated duration confidence interval.

Whole-chunk length/sample/order/nominal-time validation runs before clock validation. The exclusive input end is mapped even for partial-only chunks, so every accepted input range fits the clock horizon; a chunk extending past expiry is rejected even if its earlier complete frames would fit. All emitted frame start/end intervals are preflighted before mutation, including a frame completed using buffered PCM. `TimedFrameError::Frame(FrameError)` and `TimedFrameError::Clock(ClockError)` distinguish failures. Invalid tails, expiry and overflow emit nothing and leave PCM, expected sample position and comparison history unchanged. A valid retry at the same sample position is allowed. Known lost input must still be reflected in the next absolute sample position; errors do not fabricate silence, increment positions or automatically fault a session.

Forward gaps preserve the existing skipped/discarded-partial counts and reset comparisons immediately, including when a gap push emits no frames. Later completed recovery frames retain their actual post-gap sample position and clock intervals. Timing metadata adds at most four temporary frame-boundary records and four output wrappers per push; pending PCM and derived-state bounds are unchanged. Processing retains one fixed mapping, no timing history or extra PCM queue. Input validation is repeated by the underlying assembler; this allocating synchronous path is not a measured real-time callback or resource budget. Ordinary buffer clearing/destruction is not secure zeroization.

Five [timed-pipeline tests](../tests/acoustic-timed-pipeline.rs), run with `cargo test --test acoustic-timed-pipeline`, cover interval/nominal processing equivalence across three formats through ten-frame repetition warmup, partial/gap recovery with fractional offsets, expiry and malformed-input atomicity, backend overflow, maximum output and explicit serialized field names. The mapping's ideal sample-cadence and caller-validated clock assumptions still apply. Encoded input is supported below. No permits, source verification, capture consent, producer supervision, actual device shutdown, runtime fusion/UI, installation or live activation are introduced by this standalone path.

## Encoded Timed Input

`TimedRepetitionFrameAssembler::push_bytes(absolute_sample_position, encoding, bytes)` and `push_planes(absolute_sample_position, encoding, samples_per_channel, planes)` connect the existing packed and planar/strided converters to interval-bearing processing. Both use the format fixed by the owned sample-clock mapping; callers cannot change rate/channel count per push. Each call declares its encoding, with no activation-bound encoding check or layout negotiation. Callers may mix normalized, packed and planar input, including encodings, provided the actual samples match that fixed format and one consistent absolute per-channel sample timeline. This standalone API is distinct from the permit-checked `BufferedAcousticSession` methods with similar names.

The entire byte/view conversion precedes normalized chunk/order validation and clock checks. Malformed lengths, channel groups, plane ranges and selected samples return `TimedFrameError::Frame` without changing buffered PCM, expected positions, comparison history or output. Thus a malformed encoded chunk reports its conversion error even if its supplied position is backwards or the clock would expire. Successful conversion follows the same timed `push` path, including exclusive-end preflight, gaps, partial buffering, interval attachment and four-summary bound. Clock expiry/overflow also leaves processing unchanged after ordinary destruction of temporary samples. Valid retries are allowed; errors do not automatically stop processing or record session health. The caller must expose lost input through absolute positions or recreate processing with a fresh validated source mapping.

At most four frames of temporary normalized PCM are allocated (61,440 samples/245,760 logical bytes at 96 kHz/eight channels), in addition to existing pending PCM, FFT state and bounded timing/output metadata. Input slices and plane descriptors are borrowed for the synchronous call and not retained. Plane backing allocations and numeric strides themselves are not capped; unselected padding is ignored, not validated or scanned. Temporary PCM and audio-derived values use ordinary drop/clearing, not secure zeroization. No raw bytes or PCM are serialized or persisted. Allocation, decoding and synchronous DSP are not a measured real-time callback budget.

Five [encoded-timing tests](../tests/acoustic-timed-input.rs), run with `cargo test --test acoustic-timed-input`, compare complete batches with normalized input for all four encodings across three formats, including partial/gap processing and repetition warmup. They also cover invalid-tail/history atomicity, conversion precedence, expiry and valid retries, mixed normalized/packed/shared-plane input, ignored invalid float padding and maximum/oversized chunks. This does not verify actual source encoding, clock calibration, permissions, stream lifecycle, PipeWire mapping, participant attribution or detection accuracy. No capture, installation or live activation occurs.

## Output Contract

Serializable schema version 1 / feature version `acoustic-levels/0.1` contains:

- Frame start/duration, sample rate, and channel count.
- `rms`: square root of mean squared scalar samples across all channels. Samples are squared before pooling, so opposite-phase stereo cannot cancel as it would in an arithmetic mono downmix.
- `channel_rms`: RMS for each input channel, in input order; `max_channel_rms` preserves the loudest channel's level when other channels are quiet.
- `peak`: maximum absolute scalar amplitude.
- `clipped_sample_ratio`: fraction of all channel samples whose absolute amplitude is at least the reported `clipping_threshold`, currently 0.999. This is a near-full-scale indicator, not proof of clipping. Valid near-full-scale signals can score 100%; upstream distortion followed by attenuation can score zero.
- `rms_change`: signed difference from the previous accepted frame's pooled RMS, only when timestamps and format are contiguous. This is not a calibrated abrupt-change alert.
- `discontinuity` and an explicit unattributed-source statement. No user/channel IDs, speaker attribution, confidence scores, or moderation instructions exist in this output.

Levels are linear normalized amplitudes, not dB SPL, device volume, or perceived loudness. DC signals, speech, music, accessibility audio, and game sounds can all produce high levels. These features cannot establish intent, distinguish micspam, or identify who produced a mixed stream.

## Spectral Features

[src/acoustic/spectral.rs](../src/acoustic/spectral.rs) exposes a separate `SpectralAnalyzer` and serializable `SpectralFeatures` through the acoustic module. It accepts the same complete-frame PCM and timestamp contract as `Analyzer`, returning unchanged level features under `levels` plus schema version 1 / feature version `acoustic-spectrum/0.1`. The original `FrameAssembler` still emits level-only summaries. The optional `SpectralFrameAssembler` described below combines chunk assembly with spectral processing.

Processing subtracts each channel's unwindowed frame mean, applies a periodic Hann window, and uses RustFFT with the exact frame length (no zero padding). It pools channel powers, not waveforms or channel-normalized spectra. One-sided power doubles non-DC bins except the even-length Nyquist bin; DC is excluded. Bin spacing is 50 Hz at every supported rate. This windowing introduces leakage: frequency bins are not precise frequency-band filters.

- `centroid_hz`: power-weighted mean of retained bin-center frequencies.
- `high_band_power_ratio`: fraction of retained power in bins centered at or above the explicit `high_band_start_hz` (4,000 Hz), unavailable when Nyquist is at most that boundary. Near-Nyquist bands can have very few bins. Hann leakage means a 4 kHz tone has approximately 5/6 of its power counted in the high band at 48 kHz, not 100%.
- `positive_power_flux`: sum of positive binwise changes between successive unit-sum power distributions, clamped to `[0, 1]`. It describes spectral-shape change, not amplitude change, repetition, distortion, or an abuse probability. Pure gain changes above the numerical floor do not change it.
- `minimum_windowed_power`: fixed numerical floor of `1e-20`, applied to pooled one-sided squared FFT magnitudes divided by samples-per-channel squared and channel count. There is no Hann energy compensation. At or below the floor, centroid, band ratio, and flux are unavailable, and the previous spectrum is discarded. This is a numerical cutoff, not a calibrated audibility threshold.

Flux is unavailable on the first frame, following reset, across a timestamp gap or any format change, or when either adjacent spectrum is below the floor. Invalid input is rejected before level or spectral state changes. `reset()` discards continuity, previous spectral power, and the cached FFT plan. Output has no spectral array, PCM, participant IDs, or detection scores. The example generates opposite-phase stereo with an unchanged 1 kHz tone, a change to 6 kHz, and silence, printing summaries only.

## Combined Chunk-To-Spectral Pipeline

`SpectralFrameAssembler::new(format, origin_ns)`, `push(start_sample_per_channel, interleaved)`, and `reset(new_origin_ns)` mirror the level-only assembler. Both use the same chunk validation, sample-clock mapping, bounded partial buffer, and gap/discard reporting. `push` returns `AssemblyBatch<SpectralFeatures>`; existing level-only callers retain the default `AssemblyBatch<Features>`. Each completed frame computes levels once, then computes its spectrum while the internal PCM is temporarily available. No public raw-frame callback, PCM output, or intermediate frame queue is added.

Whole-chunk validation finishes before either framing or spectral state changes. A gap immediately resets spectral comparison/plan state, including when no complete frame is emitted. Recovery on a later push preserves `levels.discontinuity: true`, unavailable `levels.rms_change`, and unavailable `positive_power_flux`. Frames later in the same contiguous batch resume comparisons in order, subject to the spectral silence floor. Explicit reset clears both analyzers and discards buffered PCM, returning its sample count per channel. Format changes require a new combined assembler.

Input remains bounded to four frames per push, output to four summaries, and retained PCM to less than one frame between calls. Spectral state adds only the single plan/prior spectrum described below; features are not queued internally. This synchronous path still allocates and is not suitable for a real-time capture callback without a worker handoff. It performs no repetition matching, classification, source verification, capture, or bus publication.

The generated-only `assemble_synthetic_spectrum` example supplies small channel-aligned chunks with 1 kHz then 6 kHz opposite-phase stereo, leaves a partial buffer, and simulates a gap before silent recovery. Five public-API tests in [tests/acoustic-pipeline.rs](../tests/acoustic-pipeline.rs) compare direct and chunked results across 15 formats, exercise changing spectra/silence within one batch, delayed recovery/repeated gaps/reset, atomic invalid chunks, maximum output, and fractional-clock overflow. Neither tests nor examples open audio devices.

## Resources And Privacy

The [offline performance harness](acoustic-performance.md) now measures generated-PCM push wall time with separate startup and warmed summaries. Earlier unbenchmarked statements describe the initial milestones; CPU time, allocations/workspace budgets and capture-callback suitability remain unmeasured. Synthetic timing is not a real-time guarantee.

The direct `Analyzer` borrows the caller's complete-frame PCM slice and never copies or retains it. Its state consists only of previous format, end time, and RMS. Each output allocates at most eight channel RMS values; a frame is bounded to 15,360 samples.

The separate `FrameAssembler` copies PCM into one frame-sized allocation (at most 61,440 bytes) and retains fewer than 20 ms of logical PCM between calls. Input chunks are borrowed and bounded to 61,440 scalar samples; outputs are bounded to four feature records. Buffered values are overwritten with zeros before clearing on completed frames, gaps, resets, and drop. This ordinary overwrite is not guaranteed cryptographic zeroization or secure-memory erasure. No PCM is serialized, written to disk, passed to the sensor bus, or uploaded. Callers remain responsible for their own input buffers, explicit consent, and output retention.

The optional `SpectralAnalyzer` retains one FFT plan for the latest length and at most 961 normalized power bins from the previous usable frame, plus level continuity state. Each call creates temporary FFT/workspace and power buffers bounded by the supported lengths (160-1,920 samples per channel), reusing them across at most eight channels. Only the current plan is cached, not a growing map of formats. Temporary buffers contain sample-derived values and are not securely erased; the previous spectrum and even aggregate features can carry sensitive audio information. No waveform is retained between calls, but this is not an anonymity or secure-memory guarantee. Allocation and FFT planning make this unsuitable for a real-time capture callback without a separate worker; CPU/latency and exact workspace budgets remain unbenchmarked.

Tests use known silence, constant, sine, opposite-phase, and full-scale signals, plus malformed samples/formats, clipping threshold boundaries, time overflow, gaps, reconfiguration, reset, and atomic errors. They establish feature arithmetic and bounds, not measured CPU budgets or acoustic classification performance.

Nine additional framing tests compare chunked vs direct analysis at 8/44.1/48/96 kHz, exercise 10,000 small chunks without timestamp drift, check initial/repeated gaps and delayed recovery, verify whole-chunk rejection and buffer/output bounds, and cover fractional sample origins near timestamp overflow with pending PCM.

Six spectral tests cover analytic tones at multiple rates/channel counts, silence/DC/gain invariance, independent direct-DFT comparison at odd/even lengths and Nyquist, Hann leakage at the 4 kHz boundary, unequal channel power/DC offsets, continuity/reset, full-length invalid-input atomicity, and summary-only serialization. They do not measure acoustic classification accuracy or establish repetition detection.
